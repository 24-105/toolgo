# 追加ツール10個の計画

## 目的

MVPの5ツールに加えて、日常作業、開発、デザインで使いやすい10個のツールを追加します。すべてブラウザ内で処理し、入力データを外部へ送信しないToolGoの基本方針を守ります。

検索向けのページを増やすことだけを目的にせず、各ツールが実際の作業を短くできることを優先します。ページには、用途、使い方、注意点、必要に応じてFAQを用意します。

## 追加するツール

実装前はregistryで `status: "planned"` として管理し、公開できる状態になったツールを `status: "available"` に変更します。今回の10ツールは実装とbuild確認まで完了したため、すべて `available` で登録しています。slugは今後も変更しないことを基本にします。

| 順番 | ツール名                | slug                  | 主な対象                 | 処理方法・注意点                                                           |
| ---: | ----------------------- | --------------------- | ------------------------ | -------------------------------------------------------------------------- |
|    1 | URLエンコード・デコード | `url-encoder-decoder` | 一般ユーザー、エンジニア | `encodeURIComponent` などを使う。URL全体と部品の違いを説明する             |
|    2 | Base64変換              | `base64-converter`    | エンジニア、学生         | UTF-8文字列に対応する。大きなファイルの扱いには上限を設ける                |
|    3 | UUID生成                | `uuid-generator`      | エンジニア               | Web Crypto APIを使う。生成値の用途と一意性の注意を説明する                 |
|    4 | ハッシュ生成            | `hash-generator`      | エンジニア、学生         | Web Crypto APIのSHA-256などを使う。パスワード保管には使えないと明記する    |
|    5 | カラーコード変換        | `color-converter`     | デザイナー、一般ユーザー | HEX・RGB・HSLを相互変換する。不正な色値を検証する                          |
|    6 | 正規表現テスター        | `regex-tester`        | エンジニア、学生         | ブラウザのRegExpで確認する。入力文字列を外部送信しない                     |
|    7 | テキスト差分比較        | `text-diff`           | エンジニア、一般ユーザー | 2つの文章を比較する。長い入力の表示負荷を考慮する                          |
|    8 | CSV・TSV変換            | `csv-tsv-converter`   | 一般ユーザー、エンジニア | 改行、引用符、文字コードの扱いを仕様化する                                 |
|    9 | 画像圧縮・リサイズ      | `image-compressor`    | デザイナー、一般ユーザー | Canvasなどでブラウザ内処理する。元画像を変更せず、形式・容量の制限を設ける |
|   10 | Markdownプレビュー      | `markdown-preview`    | エンジニア、学生         | MarkdownをHTMLへ変換する。表示前にHTMLを無害化し、スクリプト実行を防ぐ     |

## 優先順位

最初の実装単位は、依存関係が少なく、利用目的が明確な次の5ツールとします。

1. URLエンコード・デコード
2. Base64変換
3. UUID生成
4. カラーコード変換
5. テキスト差分比較

残りの5ツールは、共通処理と入力仕様を確認した後に実装します。画像処理とMarkdown表示は、サイズ制限や安全対策のレビューを完了してから着手します。

## 共通の必須要件

- TypeScriptで実装する
- API Route、Server Action、外部APIを使わない
- 入力データをログ、解析サービス、外部サーバーへ送信しない
- 入力欄には目的が分かる日本語ラベルを付ける
- 空入力、不正入力、境界値を処理する
- 結果のコピー、ダウンロードなど、ツールに適した出力操作を用意する
- モバイル幅で操作できることを確認する
- `ToolLayout`、共通UI、共通のプライバシー表示を使う
- metadata、FAQ、使い方をツール単位で定義する
- ロジックを純粋関数として分離し、正常系・不正入力・境界値を確認する
- `status: "available"` へ変更する前に lint、test、buildと手動確認を完了する

## 実装計画

### Phase A: 仕様確定（完了）

成果物:

- 各ツールの入力、出力、エラー、上限、対応形式の仕様
- slug、カテゴリ、キーワード、metadata、FAQ
- ブラウザAPIと追加依存関係の採用判断

完了条件:

- `docs/contributing.md` の追加手順に沿って実装できる
- 外部送信なし、静的export対応、安全対策を確認できる

### Phase B: 共通基盤の確認（完了）

成果物:

- 変換結果のコピー・ダウンロードUI
- 2つの入力欄を使う比較UI
- ファイル選択、サイズ表示、処理中表示、失敗表示
- Markdown表示のHTML無害化方針

完了条件:

- 同じUIを各ツールへコピーせず再利用できる
- 共通化によって既存5ツールの表示や動作を壊さない

### Phase C: 第1グループ実装（完了）

対象:

- URLエンコード・デコード
- Base64変換
- UUID生成
- カラーコード変換
- テキスト差分比較

完了条件:

- 各ツールをregistryへ登録し、一覧・カテゴリ・詳細・sitemapへ自動反映する
- 正常系、不正入力、空入力、境界値のテストがある
- 主要ブラウザとモバイル幅で確認済み

### Phase D: 第2グループ実装（完了）

対象:

- ハッシュ生成
- 正規表現テスター
- CSV・TSV変換
- 画像圧縮・リサイズ
- Markdownプレビュー

完了条件:

- Web Crypto、ファイル処理、HTML表示の安全性を確認する
- 入力サイズや対応形式を画面に明記する
- 長い入力でも画面が崩れず、処理失敗を利用者へ伝えられる

### Phase E: 公開前レビュー（build確認まで完了）

確認項目:

- 10ツールのmetadataと日本語が自然である
- ツール一覧、カテゴリ、関連ツール、パンくずが正しい
- canonical、OGP、sitemap、robotsに意図しないURLが含まれない
- コンソールエラー、外部通信、危険なHTML実行がない
- `npm run format:check`、`npm run lint`、`npm run build` が成功する

format、lint、TypeScriptを含むbuild確認まで完了しています。公開前には、主要ブラウザでの手動操作確認を行います。

## 追加しない機能

今回の10ツールでは、ログイン、サーバー保存、共有用バックエンド、外部API連携、広告表示、ユーザー行動の追跡は追加しません。重い処理が必要になった場合も、まずWeb Workerなどブラウザ内の仕組みで解決します。
