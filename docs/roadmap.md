# ToolGo Roadmap

## プロジェクト概要

ToolGoは、ブラウザだけで完結する無料ツール集です。入力データは原則としてサーバーへ送信せず、バックエンドを持たない静的WebアプリとしてGitHub Pagesへ公開します。

対象ユーザーは一般ユーザー、エンジニア、デザイナー、学生です。短時間で使える、説明が明確で、軽量なツールを継続的に追加します。

## ゴール

短期的には、5つの代表的なツールを安定して提供できるMVPを公開します。中長期的には、ツール追加の手順を標準化し、既存コードへの影響を抑えながら100〜200以上のツールを運用できるプラットフォームにします。

設計上の優先順位は、保守性、プライバシー、アクセシビリティ、SEO、表示速度、追加開発のしやすさです。

## MVP定義

MVPは、共通UI、静的ビルド、SEOの基本設定、以下5ツール、最低限の品質確認、GitHub Pagesへのデプロイを満たした状態とします。

- JSON Formatter
- Password Generator
- QR Code Generator
- Character Counter
- Age Calculator

広告、ログイン、ユーザーデータ保存、サーバーAPI、複雑な履歴機能はMVPの範囲外です。

## Phaseごとの成果物

### Phase 0: 設計・ドキュメント

成果物は `README.md`、`docs/roadmap.md`、`docs/architecture.md`、`docs/contributing.md`、`docs/mvp.md` です。ツール追加時の判断基準と、MVPでやらないことを明確にします。

### Phase 1〜3: 基盤・デザイン・共通レイアウト

Next.jsの静的export環境、Tailwind CSS、shadcn/ui方針、共通コンポーネント、レイアウト、エラーページ、モバイル表示を整備します。ツール固有のUIはこの段階では作りません。

Phase 1では、Next.js App Router、TypeScript、Tailwind CSS v4、ESLint、Prettier、静的export、GitHub Actions CIの最小構成を実装済みです。`src/app/page.tsx` は基盤確認用のプレースホルダであり、ツール本体はまだ含みません。

Phase 2では、デザイントークン、Blue/Cyanの配色、ライト・ダークテーマ、Lucide Icons、Button、Input、Textarea、Label、Card、Badgeを実装済みです。角丸と影を抑え、情報密度と可読性を優先した共通部品を `src/components/ui` に集約しています。

Phase 3では、永続左サイドバー、検索・テーマ切替を備えたTopbar、カテゴリ導線、SiteFooter、レスポンシブな`ToolLayout`を実装済みです。`/tools` と `/categories` に共通レイアウトの利用例を置き、パンくず、プライバシー表示、使い方枠、関連ツール枠を確認できるようにしています。

Phase 4では、ページmetadata、canonical、OGP、favicon、`sitemap.xml`、`robots.txt`を静的生成する仕組みを実装済みです。公開URLは`NEXT_PUBLIC_SITE_URL`と`NEXT_PUBLIC_BASE_PATH`で切り替えられます。

Phase 5では、`src/features/tools/registry.ts` と `types.ts` を追加し、5つのMVPツールをmetadataとして登録しました。registryを情報源に、ツール一覧、ツール詳細の静的ルート、SEO metadata、sitemapを自動生成します。Phase 6では各ツールの画面コンポーネントをregistryへ接続し、MVPの5ツールを公開できる状態にしました。

### Phase 4〜6: 発見性とツール基盤・MVPツール

各ツールのmetadataを一元管理し、一覧ページ、カテゴリ、静的ルート生成、OGP、サイトマップへ接続します。Phase 6では、5つのMVPツールをブラウザ内で実装し、入力検証、コピー・ダウンロード、エラー表示、主要なキーボード操作に対応しました。ツールは独立したモジュールとして追加できるようにしています。

### Phase 6〜8: MVP完成・公開

5ツールを実装し、入力バリデーション、コピー・ダウンロード、キーボード操作、主要ブラウザ確認を行います。GitHub Actionsで静的ビルドし、GitHub Pagesへ公開します。

Phase 7では、広告を初期状態で無効にしたまま、共通の広告枠と導入方針を整備しました。広告サービス、広告ID、同意・プライバシー表示は人間側の確認が必要なため、設定が揃うまで実広告を読み込みません。

Phase 8では、`deploy-pages.yml` を追加し、`main`から作成したタグを選んだ手動実行だけで静的exportをGitHub Pagesへデプロイできるようにしました。workflowはタグのコミットが`main`の履歴にあることも検証します。公開前後の確認項目は `docs/release-checklist.md` にまとめています。公開URL、独自ドメイン、利用規約、問い合わせ先などは人間側で確定します。

### Phase 9〜10: 拡張運用

検索と入力途中の候補表示を実装しました。今後はカテゴリ、関連ツール、共有可能なURL、テスト自動化、パフォーマンス計測、追加レビューフローを整備し、規模拡大による重複や品質低下を防ぎます。

Phase 9へ進む前段として、MVP後の追加ツール10個を `docs/tool-expansion-plan.md` に定義しました。まず5個ずつ2グループに分け、共通基盤、入力仕様、安全対策を確認しながら実装します。

日常生活向けの追加ツール5個は `docs/daily-tools-plan.md` に定義し、実装済みです。給料の手取り計算は計算年を選ばない概算方式とし、制度変更時に前提を見直します。

## 将来的な拡張

- カテゴリ・タグ・キーワード検索
- お気に入りや最近使ったツール（ブラウザ内保存のみ）
- 多言語対応
- PWA、オフライン利用
- Web Workerによる重い処理の分離
- 入力データを送信しないことを検証するプライバシー表示
- ツールごとのユニットテスト、E2Eテスト、性能予算
- コミュニティ向けのツール追加テンプレートとレビュー基準
