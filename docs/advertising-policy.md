# ToolGo 広告方針

この文書は、ToolGoへ広告を追加するときの設計方針と、人間側で必要な確認事項をまとめたものです。広告収益よりも、入力データを外部へ送信しないこと、ツールを使いやすく保つこと、表示速度を守ることを優先します。

## 現在の実装状態

AdSenseの共通スクリプトは、Publisher IDが設定された本番ビルドで読み込みます。現在のPublisher IDは `ca-pub-5792181255807252` です。`NEXT_PUBLIC_ADS_ENABLED` が `true` でない場合は、広告用の外部スクリプトを読み込みません。

広告用の`AdSenseScript`と手動配置用の`AdSlot`を実装しています。共通スクリプトはルートレイアウトから全ページの`head`へ読み込みます。手動広告枠は広告枠IDが設定された場合だけ表示します。広告事業者のCookie同意処理はまだ追加していません。

有効化には本番ビルドで`NEXT_PUBLIC_ADS_ENABLED=true`と`NEXT_PUBLIC_ADSENSE_PUBLISHER_ID`が必要です。手動広告枠を使う場合は`NEXT_PUBLIC_ADSENSE_SLOT_ID`も設定します。開発環境では表示しません。未設定時に空広告やダミー文言は出さず、スクリプトも読み込みません。

## 掲載場所

広告を表示する場合も、次の場所に限定します。

- ホームのツール一覧より下
- ツールの結果・使い方より下

次の場所には広告を置きません。

- 入力欄と実行ボタンの間
- 結果表示のすぐ隣
- エラー表示やコピー・ダウンロード操作の近く
- パンくず、ヘッダー、サイドバー

広告がツールの操作に見えないよう、「広告」と明示します。広告を閉じるために入力内容を保存したり、サーバーへ送信したりしません。

## 導入条件

広告サービスを選ぶときは、次を満たすことを確認します。

- GitHub Pagesの静的サイトで利用できる
- ユーザー入力やツールの結果を広告サービスへ送信しない
- 外部スクリプトの読み込み量と表示速度への影響を確認できる
- Cookie、アクセス情報、広告の個人化について利用者へ説明できる
- キーボード操作、スマートフォン表示、広告ブロッカー環境を確認できる
- 広告が偽のボタンやダウンロードリンクに見えない

個人化広告を使う場合は、技術的に表示できることだけで判断せず、同意画面、プライバシー告知、Cookieの扱いを確認してから有効化します。

## 人間側で必要な作業

- [ ] 広告サービスと掲載形式を選ぶ
- [ ] 広告サービスの利用規約とToolGoの公開方針を確認する
- [ ] Publisher ID、広告枠ID、ドメイン確認など必要なアカウント設定を行う
- [ ] 個人化広告を使うか決める
- [ ] Cookie・同意・プライバシーに関する表示を決める
- [ ] `NEXT_PUBLIC_ADS_ENABLED` と広告IDの設定値を安全に管理する
- [ ] 自動広告を使う場合はPublisher IDだけで有効化し、手動広告を使う場合は広告枠IDも設定する
- [ ] 実広告を表示した状態で、主要ブラウザ・スマートフォン・広告ブロッカーを確認する
- [ ] GitHub Pagesの本番環境で広告表示、表示速度、レイアウト崩れを確認する

これらの判断と契約情報が揃うまでは、広告の継続表示を開始・判断しません。設定を有効にする場合も、審査状況、同意要件、表示品質を確認したうえで運用します。
