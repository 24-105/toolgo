# ToolGo UI Design Principles

## Goal

ToolGoは、ログインや説明を必要とせず、目的のブラウザツールをすぐ使える公開Webサービスです。デザインは「SaaS管理画面を再現すること」ではなく、日常的な作業を短い導線で完了できることを最優先にします。

対象ユーザーは一般ユーザー、エンジニア、デザイナー、学生です。開発者向けの信頼感を持ちながら、専門知識がなくても使える明快さを保ちます。

## Product Surface

ToolGoには2つの画面領域があります。

1. **Public Tool Surface**: ツールを使う画面。すべてのユーザーにとって主役であり、入力、実行、結果の確認を最短距離で行えるようにする。
2. **Discovery Shell**: ツールを探す画面。Dashboard、カテゴリ、検索、最近使ったツールなどを提供し、公開ツールが増えたときの発見性を支える。

Discovery Shellは補助的な構造です。ツール画面を管理画面のように複雑にしたり、アカウント作成を促したりしません。

## Visual Identity

既存サービスの見た目を模倣せず、ToolGo固有の落ち着いた実用性をつくります。

- Primary: Blue `#2563EB`
- Accent: Cyan
- Background: Soft cool gray
- Surface: White
- Success: Green
- Warning: Amber
- Danger: Red

Blueは主要操作と現在地、Cyanは補助的な強調に使います。オレンジを主要アクセントにしません。グラデーション、ネオン、発光、ガラス表現は使用しません。

## Mascot Logo

参考画像の黒白の小さなカエルを、ToolGoのマスコットとして使用します。黒鉛色・アイボリー・Cyanの小さなアクセントに限定し、写真の背景や指先は使いません。

ロゴはヘッダー、favicon、空状態や準備中状態などの軽い遊び心が許容される場所に使います。ツールの入力・結果・エラー表示など、作業の正確さが重要な領域には置きすぎません。小サイズでも認識できるシンプルなシルエットを維持し、毎回別の表情やイラストへ変化させないことでUIの統一感を保ちます。

## Style

目指す印象は、minimal、calm、functional、trustworthy、production-readyです。

- ツールの操作を視覚的に最優先する
- 余白は確保するが、情報を過度に大きく見せない
- カードの乱立や巨大なヒーロー領域を避ける
- 境界線を基本とし、影は非常に薄くする
- 角丸は小〜中程度に統一する
- アニメーションは状態変化の理解に必要な場合だけ使う

## Components

Tailwind CSS、shadcn/uiの設計思想、Lucide Iconsを使用します。共通UIは `src/components/ui` に集約し、ツール固有の見た目を各ページへコピーしません。

入力、ボタン、カード、バッジ、エラー表示は、キーボード操作、明確なフォーカス表示、無効状態、モバイル幅を標準で扱います。アイコンは意味を補助するために使い、アイコンだけで重要な操作を表しません。

フォームラベルは共通の`Label`または`.tool-editor-field-label`を使い、ブロック表示と一定の行間で左右の入力欄の開始位置を揃えます。チェックボックスは1rem角を基準にし、テーマ色と2pxのキーボードフォーカス表示を持たせます。

保存済みのテーマはページの初期描画前に適用し、リロードやページ遷移時にライト・ダークテーマが一瞬切り替わって見えないようにします。

## Typography

文字の階層を明確にします。ツール名、説明、入力ラベル、結果、ヘルプを区別し、コードやJSONなどの出力は読みやすい等幅フォントを使えるようにします。

ユーザー向けの説明は短く具体的にし、専門用語だけで操作を説明しません。SEO用の文章と画面上の操作説明は、必要に応じて役割を分けます。

画面上の文言は [日本語UI文言方針](language-policy.md) に従い、日本語を基本とします。ブランド名やJSONなどの標準名を除き、英語のメニュー名や状態表示を残しません。

### 共通の見た目の基準

ページをまたいだばらつきを防ぐため、次の基準を共通で使います。

- フォントは`Inter`を優先し、日本語は`Hiragino Kaku Gothic ProN`、`Hiragino Sans`、`Yu Gothic`、`Meiryo`の順でフォールバックする
- 本文は`0.875rem〜0.925rem`、補足は`0.75rem〜0.8rem`、見出しは共通の`.page-title`を使う
- 文字の太さは、通常`400`、ラベル・一覧項目`600`、見出し・主要操作`700〜800`を目安にする
- ページタイトルは`1.75rem〜2.5rem`、行間は`1.15`、本文は`1.5〜1.85`を目安にする

## Layout Tokens

幅、余白、線、角丸は、ページごとに個別の値を増やさず、次の基準に合わせます。

- ページ全体の最大幅は`72rem`
- ツール操作・一覧の最大幅は`56rem`、説明文や規約本文の最大幅は`48rem`
- 余白は`0.375rem`、`0.5rem`、`0.75rem`、`1rem`、`1.5rem`、`2rem`、`3rem`の段階を基本にする
- カードの標準内側余白は`1.5rem`、小さな情報カードは`1.125rem〜1.25rem`
- 通常の境界線は`1px`、キーボード操作のフォーカス表示は`2px`
- 角丸は小`0.375rem`、標準`0.5rem`、大`0.75rem`の3段階だけを使う
- 影は`shadow-sm`相当の薄いものに限定し、情報の区切りは境界線を優先する
- 色はCSS変数のテーマ色を使い、ページやツール内で色を直接指定しない。QRコードの読み取りに必要な白背景など、機能上必要な例外は除く
- 対になる入力欄と出力欄がある場合は、カードヘッダー、タイトル、ラベルを含む開始位置、フィールドの高さを揃える。カードヘッダーには`.tool-editor-card-header`、タイトルには`.tool-editor-card-title`、ラベルには`.tool-editor-field-label`、コード・JSON系の複数行フィールドには`.tool-editor-field`を使い、左右の比較領域で同じ高さにする

### 要素間の間隔

- ラベルと入力欄、見出しと短い補足は`0.5rem`（`gap-2`または`space-y-2`）を基本にする
- 同じ役割のボタンや選択肢を横並びにする場合は`0.5rem`（`gap-2`）を空ける
- 入力欄・結果表示・エラー・補足文など、役割が異なるブロック同士は`0.75rem〜1rem`（`gap-3`〜`gap-4`）を空ける
- プレビュー枠とダウンロード・コピーなどの後続操作は、視認性を優先して最低`1rem`（`gap-4`）を空ける。親要素の`space-y`または`gap`で管理し、子要素の個別マージンだけに依存しない
- カードや説明セクションなど大きなまとまり同士は`1rem〜1.5rem`（`gap-4`〜`gap-6`）を空ける
- 縦に並ぶフォームグループの`label`は`display: block`（`block`）にし、ラベル・コントロール・次の操作の間隔が親の`space-y`または`gap`で確実に効くようにする
- 共通フィールドの見た目を調整するクラスで`margin: 0`を指定し、親の`space-y`や`gap`を打ち消さない。要素が隣接して見えないか、空状態・エラー表示・ボタン・ダウンロード操作まで含めて確認する

## Navigation

デスクトップでは、ツール数が増えたときの発見性を保つために、左サイドバーとTopbarを使えます。ただし、必須なのは次の導線だけです。

- Dashboardまたはホーム
- Tool Library
- ツール検索
- カテゴリ

Favorites、Recent、Settingsなどは、実際の機能が実装されるまで主要導線に見せません。ユーザーメニュー、通知、Integrationsも、ログインや通知データなどの実体がない段階では装飾的なダミーとして追加しません。

モバイルではサイドバーを横スクロール可能な簡潔なナビゲーションへ変換し、ツール操作領域を圧迫しないようにします。

## Tool Page Layout

各ツールページは次の順序を基本とします。

1. 現在地（パンくずまたはカテゴリ）
2. ツール名と一文の説明
3. 入力と主要操作
4. 結果とコピー・ダウンロード操作
5. エラー、注意事項、使い方
6. 関連ツール

入力データがブラウザ内で処理されることを、ツール利用の近くで明示します。ツール画面にDashboardのメトリクスや不要なステータス情報を持ち込みません。

## Dashboard / Discovery

Dashboardはマーケティング用のランディングページではなく、ツールへのショートカットと状態を整理する入口です。表示する情報は、利用可能なツール、カテゴリ、検索、最近使ったツールなど、次の操作につながるものに限定します。

ホームの「目的から探す」は、カテゴリ名を並べるだけにせず、利用者がやりたいことを選ぶと代表的なツールをその場で確認できる導線にします。目的は「文章や文字を整える」「数字・お金・日付を計算する」のように操作や成果が想像できる日本語で表し、選択肢を増やしすぎず、必要に応じてカテゴリ・検索へ進める構成にします。選択状態はキーボードでも確認でき、表示されるツールへのリンクは通常のフォーカス表示を持たせます。

典型的な構成は次のとおりです。

- Dashboard
- Tool Library
- Categories
- Favorites（ブラウザ内保存を実装した後）
- Recent（ブラウザ内保存を実装した後）

## Inspiration

情報設計、ナビゲーション階層、一定の情報密度、余白の考え方はGitHub、Linear、Vercel、Cloudflare Dashboardなどを参考にできます。ただし、ブランド、配色、タイポグラフィ、アイコン、コンポーネントの見た目は模倣しません。

ChatGPT風の会話UI、AIスタートアップ風の巨大なヒーロー、未来的な装飾、過度なグラデーションは採用しません。

## UX Principles

すべてのページは次の問いに答えられる必要があります。

- ここで何ができるか
- 今どこにいるか
- 次に何をすればよいか

ログイン、通知、設定などの「存在しそうなUI」を先に作るのではなく、実際に価値のあるツール操作と発見性を先に作ります。迷った場合は、見栄えより使いやすさ、管理画面らしさよりツールの完了率を優先します。
