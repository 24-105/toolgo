# Contributing to ToolGo

新しいツールは、利用者にとって明確で、ブラウザ内で完結し、既存ツールへ影響を与えない形で追加します。実装開始前に、重複ツールがないかと静的export・プライバシー要件を確認してください。

## 新しいツールの追加手順

### 1. 仕様を決める

ツール名、slug、対象ユーザー、入力、出力、エラー条件、処理がブラウザ内で完結することを整理します。MVP対象か、どのカテゴリに属するかも決めます。

### 2. フォルダを作成する

`src/features/tools/<slug>/` を作成します。slugは英小文字とハイフンのみを使い、既存slugと重複させません。

```text
src/features/tools/<slug>/
  metadata.ts
  <ToolName>.tsx
  logic.ts
  logic.test.ts
```

### 3. metadataを追加する

`metadata.ts` に `ToolMetadata` を定義し、`name`、短いdescription、category、keywords、MVP対象かどうかを記述します。titleやdescriptionは画面と検索結果の両方で意味が通る文章にします。

### 4. ロジックを実装する

変換、計算、検証は `logic.ts` の純粋関数を中心に書きます。`window`、`document`、`navigator` などのブラウザAPIは必要な箇所だけで使い、入力データをネットワークへ送信しません。安全な乱数が必要な場合はWeb Crypto APIを使います。

### 5. 画面を実装する

`<ToolName>.tsx` は共通の `ToolLayout` とUI部品を使います。必ず次を用意します。

- ラベル付き入力欄
- 初期状態、成功状態、エラー状態
- キーボード操作と明確なフォーカス表示
- モバイル画面での操作性
- 処理がブラウザ内で完結することの説明

### 6. registryへ登録する

`src/features/tools/registry.ts` にmetadataと画面を登録します。登録によって一覧、静的ルート、サイトマップ、関連ツールに接続される設計とし、ページ側にツール固有の分岐を追加しないことを目指します。

### 7. テストを書く

`logic.test.ts` に正常系、空入力、境界値、不正入力、タイムゾーンやUnicodeなど仕様に関係するケースを追加します。UIを含む場合は、主要な操作とエラー表示も確認します。

### 8. 動作確認する

```bash
npm run lint
npm run test
npm run build
```

主要ブラウザとモバイル幅で確認し、静的export後のURL、リロード、コピー・ダウンロード、キーボード操作、コンソールエラーを確認します。

### 9. Pull Requestを作成する

変更内容、利用例、未対応事項、ブラウザAPIや依存ライブラリの採用理由を記載します。レビューでは機能だけでなく、アクセシビリティ、プライバシー、SEO、既存ツールへの影響を確認します。

## 追加時の禁止事項

- API Routeやサーバーへのデータ送信を追加しない
- ツール内に共通UIをコピーして独自実装しない
- 仕様にない入力を暗黙に破棄しない
- `any` で型エラーを隠さない
- 大きな依存ライブラリを機能確認なしで追加しない
- ユーザー入力をログや解析サービスへ送信しない

## レビュー完了条件

metadata、静的ルート、ToolLayout、エラー処理、テスト、READMEまたはヘルプ文言が揃い、`lint`、`test`、`build` が成功していることを完了条件とします。
